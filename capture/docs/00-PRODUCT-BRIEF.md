# Capture — 产品简报 (00)

## 1. 一句话定位

> **“给作家与内容创作者的 AI 创作工作室：从灵感卡片到故事、分镜、成片，一气呵成；以对话作为主控制方式。”**

## 2. 命名

- 工作名：Capture
- 中文搜索友好别名：小说工坊、分镜工坊、剧情视频工坊（PR 阶段再定正式名）

## 3. 目标用户（用户画像）

| 用户画像 | 需求 | 频率 | 痛点 |
|---|---|---|---|
| **A · 网络小说作者**（1.5k-8k 字/章、追更流） | 章节大纲 → 接续写作 → 角色库 → 连载可视化 | 每天 | 角色细节容易遗忘；设定散落 |
| **B · 短剧 / 微短剧编剧** | 剧本（场景/节拍） → 分镜（镜头清单） → 预览成片（30—90秒） | 每周 | 文字→镜头翻译耗时；人物一致性 |
| **C · 漫画/轻小说 UP 主 / 视频博主** | 有概念 → 角色图与场景 → 图文混播视频 | 每周 | 没有资产编排，图与视频难以复用 |
| **D · 独立视频创作者 / 宣传片** | 高光名场面 → 片段 → 预告片（30s/60s/90s） | 每月 | 无法“只生成最抓眼的一幕” |

非目标（明确排除）：

- 不做剧集分发/实时变现（只产出交付物）
- 不做复杂协作/多人编辑（单用户单会话 + 智能体可分叉）
- 不做 DRM/版权分发（作品归用户所有；导出文件即可）

## 4. 核心价值主张

1. **对话优先（Dialogue-first）**：所有变更（写作、拆分镜、生成图）可以在聊天中完成；UI 是把结果以**结构化、可编辑**形式呈现，而不是生成器黑盒。
2. **以资产保证一致性（Consistency by assets）**：角色、道具、场景、风格 = 一等实体，可被所有作品/分镜复用，生成时自动注入“身份锁定”提示词。
3. **渐进式保真（Gradual fidelity）**：文本 → 结构（分镜） → 静图 → 镜头视频 → 全片视频。每层都是独立可编辑、可重新生成的产物，上层变化不打乱下层。
4. **协作写作智能体（Agents that co-write）**：利用 DSH agent/subagent：大纲智能体、风格/一致性智能体、镜头导演智能体、预告片剪辑智能体等，各自拥有限定范围的上下文。
5. **来源追溯与可复现（Provenance & reproducibility）**：每张图、每段片段都记录源镜头、资产版本、提示词、种子、模型；重新生成 = 完整重建。
6. **交付物（Deliverables）**：所有最终产物以 DSH `present()` 文件 + `deliverable` 引用形式进入会话，便于后续智能体复用或用户导出。

## 5. 主要功能域（Features）

F1 **作品与章节**：work（作品）、chapter（章节）、scene（场景）；Markdown + 快速结构化（大纲、节拍）。

F2 **剧本 & 分镜**：play（剧本）、镜头清单、每个镜头：旁白/对白、动作、镜头、时长、转场、音乐/音效提示、参考。

F3 **资产库**：character（角色）、prop（道具）、location（地点）、style pack（风格包）；复用与版本管理；身份锁定（参考图 + 描述）。

F4 **AI 生成**：角色图 / 镜头静帧 / 镜头视频 / 完整预告片 / 预告片剪辑器。使用已配置（账户）模型 + 回退。

F5 **资产编排 & 一致性**：把人物/场景/道具绑定到镜头；生成时打包身份锁定 + 风格种子。

F6 **分支 & 迭代**：将章节 / 分镜清单 / 镜头分叉为 A/B 变体；比较；选择胜出。

F7 **高光名场面 & 宣传片**：从作品/剧本选择节拍 → 生成预告片（30/60/90秒）+ 无字幕/配乐版本。

F8 **智能体协作**：专用智能体提供“生成章节大纲”“下一场景”“从节拍生成分镜清单”“一致性检查”“预告片剪辑”“重写对白”；它们以差异（diff）形式写入同一产物。

F9 **交付物 & 导出**：导出 .docx/.md 剧本、.csv 分镜清单、图片/视频和预告片 mp4。使用 `present()` + 工作区下载。

## 6. 非功能目标

- 可离线（无外部服务时，AI 生成禁用，但创作/编辑/资产/导出仍可用）。
- 生成离线不阻塞：所有长任务走作业 + 进度 + 取消。
- 隐私：用户数据仅本地（`$DSH_HOME/.../capture/`），除非用户显式使用 DeepSeek 账户/图像 API。
- 可恢复：会话重启、重放不破坏产物（产物是会话事件 + 投影；仅派生状态）。
- 可测：_host 冒烟 + 媒体桩管道_，无需真实生成。

## 7. MVP 切分（阶段 1-3）

- **阶段 1（MVP-A，4-6 周）**：作品/章节文本 + 剧本/分镜增删改查 + 资产库增删改查 + 对话驱动（智能体在结构化产物上提出差异）。不含生成。
- **阶段 2（MVP-B）**：角色与镜头静帧生成（文生图）+ 一致性锁定 + 来源追溯。单提供商优先。
- **阶段 3（MVP-C）**：镜头/完整视频生成 + 预告片剪辑（ffmpeg 拼接/裁剪）+ 导出。
- **阶段 4（打磨）**：多提供商比价/排队、分支对比 UI、时间线编辑器、模板/市场。

## 8. 业务指标（成功指标）

- 首次分镜清单耗时（从空作品到可拍分镜）< 15 分钟（智能体辅助）
- 资产复用率 ≥ 40%（同一资产被 ≥ 2 个镜头复用）
- 重新生成浪费：重掷镜头静帧中位数 ≤ 2 次
- 智能体编辑保留率 ≥ 80%（无需人工重写即被接受）
- 0 个 P0 级问题因生成阻塞整个 UI

## 9. 硬要求（Constraints）

- 必须是 DSH Bundle（profile `bundles` + patch），Host API 从 `cordis` 注册服务，客户端作为 React 工厂（不重复引入 React）。
- mac 桌面优先；网页版后续（同一 Web UI）。
- 存储：主机侧服务 / 存储域；投影只读，派生状态来自会话 + 插件存储。
- 所有用户数据仅在 `DSH_HOME`；无遥测（后续可选，默认关闭）。
- 生成使用用户现有的 DeepSeek / 账户配置；不要嵌入密钥。API 密钥来自环境变量 `DSH_*`。

## 10. 风险

| 风险 | 缓解措施 |
|---|---|
| 生成提供商不稳定 / 成本高 | 提供商抽象层 + 免费模拟生成 + 缓存 |
| 角色一致性提示词工程复杂 | 资产锁定 + 参考图 + 固定种子；A/B 差异比较 |
| 智能体误编辑（破坏作品） | 基于事件追加 + 类 git 差异 + 软撤销 |
| 数据模式迁移成本 | 状态版本 + 从第 1 阶段开始的迁移测试 |
| 视频生成时间长 / 界面长任务 | 作业 + 进度 + 可取消 + 后台 |
| App.asar API 不匹配 | `compat-check.ts` 从提取包的 typing 做发现；D0 操作在“开放问题”中 |

## 11. 验收定义（v1 完成定义）

- 用户能创建项目 → 章节 → 由聊天创建分镜清单 → 添加资产 → 生成角色图 → 生成一个镜头视频 → 导出 30 秒预告片。
- 智能体可在工具中看到 Capture 能力。
- 所有生成的文件在交付物与会话中有引用。
- 测试：主机冒烟 + 客户端冒烟 + 兼容性检查 + 至少 1 个针对真实 dsh web 的端到端（手动）通过。
