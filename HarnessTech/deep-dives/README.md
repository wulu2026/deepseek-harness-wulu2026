# deep-dives —— 单点深潜

> 定位：对「一个具体问题 / 一个子系统」做一次深入，产出带证据链的结论。区别于 `atlas/`（全景图）——这里只管一个点，往深里挖。

## 什么时候写一篇

- 读源码卡住，花了功夫才搞懂某个机制 → 把搞懂的过程和结论沉淀下来；
- 实际动手时踩了坑、做了排障 → 记录现象、诊断、结论、复验方式；
- 想要彻底吃透某个能力缝（如 forge / liveshare）→ 写一篇专题。

## 结构约定

每篇固定五段：

1. **背景**：这个问题/子系统是什么，为什么要看它；
2. **结论**：先给结论，再展开；
3. **证据链**：`[源码路径:行号]` / `[Agent Note]` / `[PR]` 逐条对得上；
4. **复验方式**：怎么从源码重新核对这篇没写错；
5. **关联**：链接到 atlas 中负责该主题的图。

## 命名

- 文件名用 ASCII kebab-case（如 `windows-sandbox-acl.md`），内容简体中文。

*基于 dsh 0.2.2-alpha.2（2026-10-29）*
