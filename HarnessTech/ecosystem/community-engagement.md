# Community Engagement —— 怎么在社区里有效参与

> 定位： actionable 社区 참여 strategy: writing bug reports in Discussions, upvote behavior, how-to topic selection, and answer accumulation that translates into trust. Bridge with ecosystem/contributing-reality.md; long-term track progress/contribution-log.

## 1. 报 bug / 反馈：高质量贴

- Start at the official Discussions forum, not DM.
- Include: dsh version + commit hash; operating system + Node version; profile and patch combination; reproduction steps; observations; logs (redact secrets).
- Explicit expectation: team small and busy; even unaddressed issues are viewed, and load planning includes upvote counts.
. Agents summary: brief problem setups > huge dumps; attach compressed framed sniff-log.

## 2. Upvote 的策略

- Vote up problems you're genuinely affected by; don't coordinate spam.
- Add comment how it specifically blocks your work so it becomes more use-case rich.
- Link concrete impact paths (which tasks/seams affected).

## 3. how-to / blog 选题

- Pick topics rooted in real experience: where source + diagrams proved unclear.
- Use concrete evidence, code annotations, and reproducibility trace steps.
- Submit to Discussions / profile README; add your plugin or link demo if available.
- Ensure titles accurately reflect scope; avoid lore.
## 4. 社区答疑如何积累信任

- Forum answer preferred over fact-building; cite docs and source.
- Respond with bounded concise technical note including details required to derive the answer.
- Follow up with diagnosable proof rather than opinions.
- Encourage two-way network rather than broadcast.

## 5. 风险边界

- Never expose secrets; stubs always mask values.
- Avoid promising unofficial compatibility guarantees or publish rushed updates.
- Respect upstream's external PR closure while directing contributions to plugin/content channels.

## 6. 单一产出建议（按阶段）

- M0-M1: focus clarity.
- M2: ship minimal plugin.
- M3-M4: write how-to keyed to exact task.


*基于 dsh 0.2.2-alpha.2（2026-10-29）*
