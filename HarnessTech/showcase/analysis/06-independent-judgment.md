# 06 独立判断：亮点、代价与谁该关注

> 这是整套分析里唯一一篇「观点文」。前面五篇讲事实，这一篇讲我（分析者）的判断。

## 三个真亮点

**1. 全插件赌到了 agent 循环本身。** 多数 agent 框架的可替换性止步于外围工具，循环是私有内核。dsh 把循环、模型适配器、会话日志全部插件化，并用入口收敛门禁堵死绕开组合机制的捷径 [docs/architecture.md:9-45]。这带来一种罕见的实验自由：换一个循环实现和换一个工具，是同一量级的操作。

**2. 事件溯源直接消灭了 agent 测试的死结。** 模型输出的不确定性让 agent 产品的自动化测试近乎无解。dsh 的「模型可见 ⟺ 已记录」不变量 [docs/architecture.md:128] 使会话日志天然就是测试输入，无密钥回放（`test:snapshot`）让 CI 在没有 API key 的情况下跑真实会话的持久化输出比对 [vitest.snapshot.config.ts:28-32]。这是架构选择转化为测试能力的教科书案例。

**3. 门禁是 AI 编码时代的文化载体。** 330 个门禁脚本把评审判断机械化：文档代码块要过编译、文档有字数预算、UI 文案必须走 i18n 字典、入口必须显式归类。当代码生成成本趋近于零，这套「机器可执行的品味」可能是大型仓库唯一能活下去的方式。

## 三个真代价

**1. 认知税极高。** 372 个包、53 个分组、五个事件分发模式、三个事件域、能力缝三角色——在读第一行代码之前，你需要先学会两门方言（Cordis + dsh 约定）。`docs/cordis-primer.md`、`docs/architecture.md`、53 个包组 README 是硬性前置阅读。全插件换来的一切都先以复杂度形式预付了。

**2. pre-stable 的流动性。** 官方明言「会有兼容性破坏变更」[README.md:13]；`SESSION_FORMAT_VERSION` 已经迭代到 4 [types.ts:68-90]；升级指南写作有专门的 skill（`dsh-create-upgrade-guide`），说明 breaking change 是日常而非例外。会话格式有世代保留纪律兜底，但 API 消费者要有跟着升级的心理准备。

**3. 指标的形式化风险。** 逐文件 100% 覆盖率是硬门禁 [vitest.config.ts:12-16]。高覆盖本身不保证测试质量——「为满足指标而写的测试」是这类门禁的通病，需要靠 review 文化兜底，而 review 文化恰恰是最难门禁化的东西。

## 谁该关注这个项目

- **Agent infra 研究者**：这是市面上少有的、生产级强度、完整开源的 agent harness 参考实现。事件溯源的会话模型和三事件域划分值得逐字读。
- **插件作者**：能力缝三角色是清晰的能力设计模板，`dsh-plugin` topic 是入场通道。
- **AI 工程化实践者**：门禁体系本身就是最佳学习材料——如何把 review 意见变成 CI，这里有一整套现成答案。

## 一句话结论

dsh 的价值不在于它是一个「更好用的 agent 框架」，而在于它示范了一件事：**当 AI 开始大量生产代码，一个软件项目该如何重新设计自己的架构、测试与文化，才能让复杂度仍然可控。**
